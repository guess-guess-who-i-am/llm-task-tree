# 上下文生命周期：让并行分支可以连续工作

LLM Task Tree 新增上下文生命周期管理，用来解决长期项目中 Agent 对话越来越长、换新对话后丢失工作进度的问题。

## 用户能得到什么

每个并行分支都有自己的持续上下文。分支达到较高上下文占用后，系统会在下一次继续时创建新一代对话，并自动准备短交接包。交接包包含：

- 根目标与阶段目标
- 上一代的当前结果
- 已修改文件与测试结果
- 下一动作和当前分支信息

新一代 Agent 在自己的隔离 worktree 中读取交接包后继续工作。上一代 thread 会被归档，不会被删除；交接输入在本轮结束后清理，避免把运行时文件混入代码提交或任务树。

## 为什么这不是普通摘要

普通摘要只证明模型生成了一段文字。这里的验收要求是：新 Agent 必须从隔离工作目录实际读到上一代结果，并且旧 thread、交接档案和清理状态都能追踪。

## 已验证

- 两个并行分支各自从第 1 代切换到第 2 代。
- 新一代实际读取分支内交接文件中的唯一结果标记。
- 旧 thread 被归档，交接输入在完成后被删除。
- Codex 运行时测试 11/11 通过。
- 协调器、Git worktree、桌面/手机 UI 和真实 HTTP 浏览器流程通过。
- kit 与 Codex 插件 runtime 已同步。

当前 70% / 90% 是工程默认阈值，用于“偏长提示”和“下次继续时换代”，不是声称唯一理论标准。长期真实业务中是否始终抓住根目标，仍需要在具体项目中连续试跑。

## 试用

```text
打开任务图，然后启动一个自动并行任务。
```

当某个分支长时间运行后，继续该分支即可观察上下文代际和交接状态。
