# 节点资料：图片和文档

节点右上角和鱼眼标题栏的 📎 是「资料」入口，不需要先执行节点。可选择文件、拖入文件或粘贴图片。添加后默认勾选「执行时使用」，点击文件名可打开原文件；取消勾选仍保留资料。

也可以完全不打开 📎：直接把图片或文档拖到节点卡片、鱼眼中心节点或「下一步」编辑框；在「下一步」框按 ⌘V 粘贴图片也会保存为节点资料。框下直接显示缩略图/文件名、保存状态及「管理」，不自动弹出窗口，不启动模型，不把图片路径写进任务说明。连续拖入不会丢失，切换节点或子树时仍保存到拖入当时的节点。

浏览器有时只给出复制文件的绝对路径，而不是图片字节；若粘贴内容全部是本机支持的文件路径或 `file://` 地址，会读取这些明确指定的文件并保存独立副本。支持中文、空格、引号及多行路径，不执行任何路径中的命令；源文件删除后副本仍可用。不可读或不存在会就地提示。复制的文档正文、普通指令和远程链接仍正常粘贴为文字，不猜测它们是附件。

支持 PNG/JPEG/WebP、PDF、Word、RTF 和 UTF-8 文本。单文件最多 20 MiB，超过时拒绝而非截断。PDF/Word 提取全文，图片按原始字节进入视觉消息；扫描 PDF 请使用页面图片。模型是否支持视觉、上下文容量以及网关稳定性仍取决于实际服务。

## 使用规则

直接执行节点默认带上该节点勾选资料。对话输入区可取消「使用节点勾选资料」，仅对本次发送生效。未勾选的某一份资料也能点「加入本次对话」：有对话则续接，没有则打开本地输入草稿；只有点击发送才调用模型。显式附件与自动选择按附件标识去重；同一库内原文件在本轮历史中只发送一次全文，保留全部历史文字和持久引用，避免每轮累加重复正文。

并行 Planner 接收当前阶段及其有向后代节点勾选的资料，包括相关折叠子树内部节点；只在服务器端读取附件索引，不把子树全文自动展开进提示词。Worker 接收阶段公共资料和自己任务节点的资料，不自动接收兄弟任务资料。执行时从源工作目录读取附件；已提交的资料也会随 Git worktree 带入。新增任务、冲突处理和双方续接也使用相同入口。

取消勾选或本轮不用时，模型本轮请求中的历史资料引用也会过滤，不会继续重发其图片和文档全文。持久化对话不改动，历史助手文字可能已经描述资料；此选择不是「删除模型记忆」。移除节点关联后，原文件仍供已保存对话使用，其旧对话引用不再受节点库选择过滤。独立话题应新建节点或删除原对话。

## 存储与恢复

原文件及解析正文存于项目 `.task-tree-attachments/<附件标识>/`。每节点清单存于 `.task-tree-attachments/nodes/<树与节点身份摘要>.json`，记录附件标识与 enabled 选择；原子保存，同一节点的并发操作在本地服务内串行化，不同节点互不阻塞。重启/刷新后重新读取，不依赖浏览器内存。资料按 treeId + nodeId 隔离，主树与同树的折叠子树共享稳定节点身份，其它树不会串用。

附件默认纳入 Git，包括原始图片/文档、完整提取正文和节点选择清单。正常提交并推送项目后，另一电脑克隆/拉取即可恢复，无需另外复制附件目录。目录内的 Git 包含规则让 LOG 等文件也不会被项目的通用忽略规则漏掉；上传会替换旧的自动生成「全部忽略」规则。文件仍保留本地权限，API 密钥等 `.env` 配置不属于资料，继续忽略。

上传和勾选只是保存文件，不会每次自动提交或推送；在提交项目时一起纳入版本管理。删除聊天不删除节点资料；「移除」只解除关联，不删除原文件，因此原文件也继续进入 Git。任务树 Markdown 不存 Base64 或文档全文。多个独立服务器同时修改同一个项目清单尚无跨进程写锁，正常启动器复用每项目单个服务。

## 接口契约

`/api/node/materials?treeId=<树>&nodeId=<节点>`：GET 返回 `{materials}`；POST `{id,enabled?}` 添加关联（enabled 默认 true），相同 id 重复添加不重复；PATCH `{id,enabled}` 选择；DELETE `{id}` 解除关联。返回的资料包含原附件引用和 enabled。不存在节点返回 404，非法输入返回 400，跨树/节点引用返回 403。

`/api/codex/run` 的节点请求默认使用库内勾选资料，可传 `useNodeMaterials:false` 禁用；`attachments:[id]` 指定单次附件。并行运行使用临时 `contextMessages`，不替换续接对话、不把 Base64 保存进对话。

`POST /api/chat/attachments/import?treeId=<树>&nodeId=<节点>`：仅接受 `application/json` 的 `{path:<明确绝对路径或本地file地址>}`，201 返回与字节上传相同的 `{attachment}`；再复用节点资料 POST 建立默认勾选关联。相对路径/文件夹/非法 JSON 为 400；不存在文件或节点为 404；类型不支持或非 JSON 为 415；超 20 MiB 为 413。仅读取用户此次提交的文件，不遍历目录，文件和解析正文都走同一存储/Git规则。

## 验证与边界

`server/attachment-git.test.js` 用真实 Git 提交和重新克隆，验证原图字节、文档全文、勾选状态及后续上传都可恢复，并确认 `.env` 不被加入。`server/node-materials.test.js` 覆盖并发保存、重读恢复、选择、解除关联保留原文件、跨节点/树拒绝、全文、原图、折叠分支和模型续接。`server/codex-coordinator.test.js` 用隔离工作目录验证 Planner/两个并行 Worker 的真实传参和不串资料。`server/subtree-workspace-ui.test.js` 通过临时工程、HTTP 服务、Chromium 和本地模型替身验证文件选择/拖拽/粘贴、刷新、草稿、直接执行、禁用、删除聊天保留资料。

这些测试检查真实模型请求结构，但本轮没有执行用户业务节点或上传业务照片到测试模型。真实合成图的视觉能力沿用 `docs/local-image-input.zh.md` 的上一轮证据，不能由本轮测试保证网关永不重试或模型每次都正确理解。

源码扩展回归 70 项通过，安装版 Node 22 的 52 项通过，另加手机与鱼眼资料入口定向验证通过。插件 91 文件一致性检查通过，实际 5491/5866 已部署，资料接口与浏览器入口已验收，业务树和原对话哈希不变。

浏览器测试曾因外部 KaTeX CDN 未返回而卡在 DOMContentLoaded，尚未进入应用逻辑；测试现隔离无关 CDN。另一失败是并发清单添加顺序不确定，测试改为按消息类型查找原图；没有改变生产顺序。单节点直接执行的测试改为等待新 POST 返回，避免把上一轮完成状态误认作本轮完成。
