## N7 - 集成 Markdown 知识库检索面板
- Position: 740,977
- Size: 520,720
- Completion: 已完成
- Problem: 用户有 Obsidian/Copilot 风格的 Markdown 知识库，希望在任务图页面左侧直接建立 embedding 索引、检索文档、基于文档问模型，并让多模型协作能看到检索到的文献/笔记内容。
- Approach:
  - 在页面最左侧加入约五分之一宽度的知识库面板，包含知识库文件夹、embedding base_url/api_key/model、问答模型、重建索引、检索和问答入口。
  - 后端实现独立的 OpenAI-compatible embedding 索引：递归扫描默认 `knowledge/` 下的 `.md` 文件，按段落/标题分块，批量请求 `/embeddings`，保存到 gitignored 的 `knowledge-index.json`。
  - 检索时对问题重新 embedding，使用余弦相似度返回 top chunks；问答时把检索片段提供给已配置的聊天模型。
  - 多模型协作运行时可附带知识库面板最近检索到的片段，让多个模型同时看到同一批文献上下文。
  - 现有 `copilot/.obsidian` 索引只作为实现参考，不直接混用；因为 Copilot 索引文件巨大且 query embedding 必须与其 embedding 模型/维度一致。
  - 增加项目根目录 `.env` 一次性配置：多模型、每个模型的 agent.md 路径、embedding、知识库目录和 web search provider/API key 都只从 `.env` 读取。
  - 增加独立 web search provider 层，先支持 Tavily、Brave Search 和 Exa；搜索结果与本地知识库结果合并后进入知识库问答和多模型协作上下文。
  - 前端不再提供 API key、base_url、model 等配置表单，只显示 `.env` 配置状态，避免占用节点和面板空间。
  - 多模型协作运行时允许模型自主请求检索；服务端按模型请求调用本地知识库，并可按页面勾选同时调用 web search。
  - web search 增加 `searxng` provider：不需要 API key，但需要 `.env` 配置可访问且开放 JSON 输出的 SearXNG 实例。
  - web search 增加 `openwebsearch` provider：通过本地 `open-webSearch` daemon 的 `/search` 做 no-key 联网检索。
  - `打开任务图.cmd` 启动项目时会检查 `.env`，如果 `WEB_SEARCH_PROVIDER=openwebsearch` 且 daemon 未运行，会尝试自动启动 `open-webSearch/build/index.js serve`。
  - web search 配置返回 `requiresApiKey`，前端对 `openwebsearch`/`searxng` 显示“不需要 key”，不再误报“缺少 key”。
- Input: `knowledge/` 下的 Markdown 文档、`.env`、`knowledge-config.json`、`web-search-config.json`、`model-agents.json`、`model-agents/<id>.md`、当前知识库检索问题、多模型协作问题。
- Output: 左侧知识库面板、`.env.example`、`/api/knowledge/config`、`/api/knowledge/reindex`、`/api/knowledge/search`、`/api/knowledge/ask`、`/api/web-search/config`、`/api/web-search/search`、多模型 prompt 中可选注入的本地知识库和网页搜索片段、gitignored 的本地配置和索引文件。
- Metrics:
  - 用户无需打开 Obsidian，也能把 Markdown 放进默认文件夹后从页面重建索引。
  - 检索结果显示来源路径、相似度和片段内容。
  - 问答模型基于检索片段回答，并能指出上下文不足。
  - 多模型协作可选择附带最近检索片段。
  - 模型、embedding、web search 和 agent.md 路径只通过 `.env` 配置一次后复用。
  - 联网搜索结果显示来源、URL、分数和片段内容，并能和本地知识库结果一起进入模型上下文。
  - API key 不进入 `task-tree.md`。
  - 多模型协作点击运行后，即使左侧没有最近检索结果，也会按模型问题检索本地知识库并注入上下文。
  - `WEB_SEARCH_PROVIDER=searxng` 时不要求 `WEB_SEARCH_API_KEY`，但缺少 `WEB_SEARCH_BASE_URL` 会给出明确错误。
  - `WEB_SEARCH_PROVIDER=openwebsearch` 时不要求 `WEB_SEARCH_API_KEY`，并能通过本地 daemon 返回真实网页搜索结果。
  - 双击 `打开任务图.cmd` 后，如果 open-webSearch 已完成依赖安装和 build，联网搜索能力会随项目入口一起可用。
  - 知识库索引保存在 `knowledge-index.json`，建立一次后可复用；新增或修改 Markdown 后点击“重建索引”会全量重建并继续复用。
  - 点击“重建索引”后显示进度条和阶段；已有 chunk embedding 会按内容 ID 复用，只有新增或修改片段重新请求 embedding。
- Notes: 第一版没有实现真正联网搜索；当前 OpenAI-compatible chat 接口本身不保证 web browsing。要联网，需要后续增加明确的搜索 API 或 provider-specific web-search tool 配置。可选方案分两类：模型厂商内置搜索工具（如 OpenAI Responses web_search、Perplexity Sonar）和独立搜索 API（如 Tavily、Exa、Brave Search）。更通用的项目方案是先接独立搜索 API，把网页结果作为上下文喂给任意模型；厂商内置搜索适合单一模型链路。
- CurrentResult: v2 Worker N7 审计完成：`server.js` 共 9 条 knowledge/web-search 路由（config/reindex/reindex-status/search/ask + web config/search）；`searchRetrieval` 合并本地 RAG 与 5 种 web provider，空索引不阻断联网；详情见 `docs/subtree-parallel/v2-N7-findings.md`。此前实现：`.env` 配置、索引重建与 embedding 复用、openwebsearch daemon 自动 build/spawn、多模型经 N6 run 间接调用检索。
- RootCauseAnalysis: 用户看到 `openwebsearch daemon not reachable at http://127.0.0.1:3210` 的根因是双重的：(1) `open-webSearch` 从未 `npm run build`，kit 目录下也没有该包；(2) daemon 只在 `打开任务图.cmd` 启动时尝试拉起，模型协作走 `/api/knowledge/search` 时服务端直接 fetch 3210 端口，未启动则失败。`knowledge index is empty` 是独立问题（F:\empty-window 等项目未重建索引），不应与联网失败混为一谈。
- CaseStudy:
  - case 1: `copilot/.obsidian` 里已有 8 个 50MB 以上的索引分区；如果页面每次启动都全量读取，会让任务图入口变慢。
  - case 2: Copilot metadata 显示 embedding 是 `vector[3072]`；如果用户配置 1536 维 embedding 模型查询，余弦相似度无法计算。
  - case 3: 用户要求“模型能联网”，但当前 OpenAI-compatible `/chat/completions` 调用只发送文本，不自动拥有搜索工具；因此必须明确标注未实现联网，而不是在 UI 或 prompt 中暗示已联网。
  - case 4: 如果把 api_key 继续只放在网页表单或 JSON 中，多项目复用会变成重复配置；`.env` 让模型、embedding 和 web search 的密钥都在本地一次性声明。
  - case 5: 如果让每个模型共用同一个 agent prompt，会破坏模型协作里的角色差异；因此每个模型继续使用独立 `model-agents/<id>.md` 或 `.env` 指定的 agent 文件。
  - case 6: 网页里继续展示 base_url/api_key/model 会占用节点和侧栏空间，而且制造“可以在多个地方配置”的隐性状态；移除表单后，配置来源只剩 `.env`。
  - case 7: 用户以为 web search 应该是一个工具，但本地 Node 应用不能调用 Codex 会话注入的 `web` tool；因此项目内必须使用独立搜索 provider，或者接一个 no-key 的 SearXNG 实例。
  - case 8: 如果多模型协作只附带左侧“最近检索片段”，用户忘记先检索时模型仍然看不到知识库；因此模型运行接口需要支持模型主动触发检索。
  - case 9: npm 初次安装失败留下残缺 `node_modules`，导致 daemon 启动时缺 `setprototypeof`、`unpipe`；用项目内 cache + 代理执行 `npm ci` 才恢复了完整依赖树。
  - case 10: 当前树未记录 openwebsearch，但磁盘已有实现；如果直接按记忆跳过测试，会违背树回溯规则，因此本轮重新执行了真实联网测试。
  - case 11: `openwebsearch` 本来不需要 key，但前端只根据 `hasApiKey` 显示状态，导致误报“缺少 key”；应由后端返回 `requiresApiKey` 让 UI 区分 no-key provider。
  - case 12: `knowledge-index.json` 有 139MB，但 JSON 末尾残留了额外数字，导致服务端解析失败后静默回退为空索引；根因是大文件直接写入不是原子操作，半写/残留会让后续检索看起来像“没有建立索引”。
  - case 13: 全量重建 1552 个 chunk 时 embedding 服务返回 “Service load is too high”；如果没有复用旧 embedding，用户每次更新一个 md 都要承担整库失败风险。
  - case 14: 模型协作勾选联网后 0 条结果，错误同时含 knowledge empty 与 daemon not reachable；实际是 open-webSearch 未 build 且 server 未 auto-start，与本地索引是否为空无关。
- NextIdea: `F:\empty-window` 本地知识库仍为空时可点「重建索引」；日常 kit 升级只需双击 `一键更新.cmd`。
