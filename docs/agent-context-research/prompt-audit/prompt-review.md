# 原 AGENTS.md 审核结论

## 审核方法

1. 冻结原文并计算 SHA-256。
2. 将每个非空原文行标注 F00–F20 功能 ID。
3. 将包含多个句子的行拆成语句单元；标题、表格、代码和 marker 作为结构单元。
4. 为每个功能指定新入口或强制路由目标。
5. 自动验证原文恢复、功能 ID 完整性、目标文件存在和新入口字节预算。

## 原 Prompt 的优点

- 功能覆盖很完整：活树压缩、GraphState 所有权、回滚漂移、skill 路由、flow drift、step evidence、chain run 都已有明确规则。
- 对字段写法和反例描述具体，适合作为详细参考协议。
- 版本备份、二元边和用户焦点保护属于高价值安全约束，必须保留。

## 原 Prompt 的主要问题

### 1. 入口与参考手册混为一体

字段 schema、长示例、完整 checklist 和安装 stub 每轮都进入根指令，但它们只在特定写操作中需要。结果是常用的 Start/End/GraphState 规则与低频材料竞争注意力。

### 2. 同一功能重复出现

- F01/F05/F07/F08/F09 在完整协议和 `llm-task-tree:begin` merge stub 中重复。
- F13 同时在 §1c、§2、§4 和 stub 中重复。
- F12 的 schema skeleton、字段表和写法示例均在根入口，信息正确但装载时机错误。

这些重复不能直接删除；本次将完整版本保留在详细协议，只在根入口保存触发条件和不可违反的不变量。

### 3. 高风险规则靠后

F18 chain run、F19 安装 stub、F20 tool calling 位于文件尾部。原文件超过默认项目指令预算时，这些功能最容易失去可见性。新入口把 F18 路由和 F20 always-on 规则提前。

### 4. 只有自然语言要求，没有覆盖证明

原协议反复要求“不要漏”，但没有证明重构后功能仍存在的工具。本次新增逐句账本和覆盖验证器，把功能等价从主观判断改成可执行检查。

### 5. 打包脚本会破坏分层

原 `scripts/build-kit.ps1` 把根 `AGENTS.md` 复制成 kit 的完整协议。根入口缩短后，如果不改脚本，下一次 build 会把详细协议覆盖掉。本次已改为从 `llm-task-tree/AGENTS.task-tree.md` 打包。

## 重构决策

- 原文不删除：冻结副本与 `llm-task-tree/AGENTS.task-tree.md` 均保留完整内容。
- 根入口缩短：只保留 always-on 不变量、关键完成定义、工具规则和 F00–F20 路由。
- 低频细节按触发加载：tree write、flow write、chain、install 各自读取专用文件。
- 每个 critical 功能在根入口必须有直接规则或 `MUST read` 路由。
- 新 Prompt 不以“更短”为唯一成功标准；覆盖测试不通过就不能交付。

## 自动验证口径

- 原文 555 行；400 个非空行均有标签。
- 拆分出 500+ 个语句/结构单元，每个都有功能 ID、功能说明和新落点。
- F00–F20 共 21 类功能全部可从新入口触达。
- 带标签文件移除 HTML 注释后必须逐字恢复冻结原文。
- 根入口目标 <=8 KiB；详细协议和原文不受该预算删除。
