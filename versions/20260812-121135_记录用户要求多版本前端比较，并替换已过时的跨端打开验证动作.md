## N11 - 重构多树上下文与 Agent 维护闭环
- Position: 2614,982
- Size: 0,720
- Completion: 进行中
- Problem: 如何让人借助任务图舒适地形成局面感、恢复上下文并保持对模型的控制？
- Approach:
  - 保留树作为联系载体，但默认从 Current/Next 自动进入“焦点视图”，不再先适配全树。
  - 中心放大当前节点，固定显示根本任务是否达成、当前状态、卡点和下一动作。
  - 只显示通向 ROOT 的祖先、直接相关节点及少量高相关方向；其余折叠成带标题和数量的方向提示。
  - 全貌保留为用户主动切换的低频视图，沿提示展开时保持空间位置和返回线索。
- Input:
- Output: 正式任务树的语义缩放、活动主干和主干优先排布；实现见 public/app.js、public/styles.css，验收证据见 artifacts/task-tree-semantic-zoom-*.png。
- Metrics: 同任务对照当前全树视图：能否正确说出根本任务状态与卡点；找到当前节点及相关依据所需的搜索操作；是否被无关节点分散；切到全貌后能否保持方向感。
- Notes:
- CodeLoc:
- CurrentResult: 现有树已能用粗主干和语义缩放表达联系，但首次加载与刷新仍自动适配全树，用户必须自己寻找 Current/Next，其他节点同时进入视野。用户高频目标是判断根本任务是否完成、当前推进状态与卡点；现界面尚不能主动把这些相关节点送到屏幕中心，因此该目标未达到。
- RootCauseAnalysis: 第一处偏离发生在视口策略：系统把“展示完整结构”当默认任务，而用户多数时候执行的是围绕当前节点的局部判断。仅靠加粗主干仍保留了全部竞争刺激，没有按当前兴趣动态选择上下文。
- CaseStudy:
- NextIdea: 先做“当前焦点＋关系提示”只读原型：自动居中 Next，显示 ROOT 路径、卡点和一阶相关节点，其余方向折叠，并与全树默认视图对照。
