## N3 - 让 Codex 同步维护任务图
- Position: 2052,950
- Size: 400,420
- Completion: 进行中
- Problem: 多个 Agent 共用一棵树时，如何避免把全局 Next 误当作各自目标并互相覆盖？
- Approach:
  - 模型在10秒总预算内生成2–4个分支；超时或重启中断则立即生成可审核保守草案。
  - 计划阶段只拒绝精确保留路径；运行后按实际改动拦截共享状态和越界文件。
  - worker 在独立 worktree 写入并测试，coordinator 在 integration 中核验、修复与集成。
  - 默认审核只显示状态、分支和任务；设置折叠，失败分支可原地修订并局部重跑。
- Input: 当前任务树、本轮目标、可审核并行草案，以及开始与结束两次用户决定。
- Output: 带目标的自动规划、隔离并行、严格接受门禁、失败分支局部重跑与接受后节点同步。
- Metrics: 草案阶段零写入；从用户点击到草案约10秒内结束等待；受保护文件实际改动必拒绝；失败分支只重跑自身；主工作区审核前不变。

- CurrentResult: 自动规划已从历史实测167–625秒收敛为10秒总预算，本机真实接口10.46秒返回3分支草案；超时会关闭会话并降级，重启遗留的 planning 可自动恢复。开始审核默认只显示状态、分支和任务，其余设置折叠；真实三次点击、失败分支局部重跑及 kit、插件、Linux 回归通过。当前可用性问题已解决，但降级草案能否长期扣住真实业务目标仍待验证，N3整体目标不能宣称达到。
- RootCauseAnalysis: 慢的根因是10分钟等待只约束模型完成阶段，连接和会话耗时未计入；失败的根因是按“可能重叠”预拒绝宽写集，且服务重启后没有孤儿状态恢复。信息过载来自默认展开 ID、依赖、命令和写集。
- CaseStudy:
  - case 1: 主工作区已有未提交和未跟踪文件 → 快照保留用户基线，审核前主目录不变。
  - case 2: 运行期间用户再次修改同一文件 → 接受被阻断，不静默覆盖。
- NextIdea: 在一个真实业务目标上审核10秒降级草案，记录是否需要改分支或任务；若频繁修改，再优化 fallback 的目标分解。
