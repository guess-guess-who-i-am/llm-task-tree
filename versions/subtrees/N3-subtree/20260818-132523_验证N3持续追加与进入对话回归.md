## N3 - 让 Codex 同步维护任务图
- Position: 2052,950
- Size: 400,420
- Completion: 进行中
- Problem: 自动并行如何快速返回可审核分支，并在多 Agent、长期真实业务中持续抓住根本目标？
- Approach:
  - 模型在10秒总预算内生成初始草案；用户可在草案、运行、汇总和审核阶段按节点持续追加，最多同时运行4路，其余排队。
  - 计划阶段只拒绝精确保留路径；运行后按实际改动拦截共享状态和越界文件。
  - 调度器持续读取动态队列；worker 在独立 worktree 写入并测试，同类节点沿用上下文，Codex 接受任务即显示对话入口。
  - 首屏只显示编号、自然名称、状态和一句结果；完整字段按需展开编辑，新增分支立即定位。
- Input: 当前任务树、本轮目标、可审核并行草案，以及开始与结束两次用户决定。
- Output: 带目标的自动规划、指定节点持续追加、可进入并复用的 worker 对话、隔离并行、失败局部重跑与接受后节点同步。
- Metrics: 草案零写入；运行或审核阶段追加任务在同一工作区完成；计划数可超过4且峰值不超过4；worker 入口可打开；保护文件越界必拒绝；失败只重跑自身；审核前主工作区不变。

- RootCauseAnalysis: 调度器原先只读取启动时的任务快照，运行中新增分支不会进入执行前沿；worker 线程虽已记录，前端却只有不明显的箭头且没有专用打开通道。
- CaseStudy:
  - case 1: worker 尚在运行时追加节点 → 旧调度器忽略新任务 → 动态队列必须每轮读取当前分支。
  - case 2: worker 已有 threadId 但只有箭头链接 → 用户无法确认入口 → 使用明确文字按钮和专用打开 API。
- NextIdea: 在真实业务中连续追加两轮并指定同一节点，进入多个 worker 对话，核验排队、上下文继承和长期目标是否仍符合用户预期。
