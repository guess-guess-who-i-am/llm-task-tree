## N11 - 重构多树上下文与 Agent 维护闭环
- Position: 2613,961
- Size: 0,720
- Completion: 进行中
- Problem: 如何让人隔天快速恢复上下文，同时让 Agent 及时维护树和执行流程？
- Approach:
  - 将每日“回顾”改为决策总览：首屏只回答根本目标、当前局面、阻塞与推荐下一步。
  - 仅列未完成且有 NextIdea 的可选方向；全部节点压成标题加状态的一行索引，详情按需进入关系图。
  - 当前局面优先读取 Next 节点的首条结果与根因，避免过期 Current 污染。
- Input:
- Output:
  - public/index.html、public/app.js、public/styles.css # 决策总览
  - scripts/test-project-overview-ui.mjs # 交互与信息量测试
  - artifacts/project-overview-desktop.png、artifacts/project-overview-mobile.png # 实测截图
- Metrics: 打开后可在一屏识别目标、当前局面、阻塞、推荐下一步；只显示必要候选和一行节点索引；可直接设置 Next 或定位节点；桌面与 390px 无横向溢出。
- Notes:
- CodeLoc:
- CurrentResult:
  - 当前活动方法树有 14 个节点；虽然已通过字段与总大小门禁，用户仍明确不愿打开任务图。
  - 聊天能直接回答问题，而任务图要求主动打开、定位节点并阅读多字段，恢复上下文的操作成本更高。
  - 现有“回顾”只压缩文字，没有把“全局状况、节点状态、下一步决策”变成一个可扫读的操作界面。
- RootCauseAnalysis: 当前优化目标偏向让 Agent 存得正确，而不是让用户看得更快；信息虽已精炼，入口仍以节点和字段为中心，缺少按决策优先级组织的渐进展示。
- CaseStudy:
- NextIdea: 先把决策总览的内容与交互写成失败测试，再实现渲染、设置 Next 和节点定位，并完成桌面与 390px 验证。
