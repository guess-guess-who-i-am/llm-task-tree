# README 演示视频制作方法

## 来源复盘

复盘对象是 Codex 对话 `019fd550-6533-7103-9891-d1df8fbb693f`。该对话最终采用的不是生成式视频，也不是直接录屏，而是以下流程：

1. 先研究官方参考片：用 DeepMind 的科学问题叙事、Apple 的视觉克制、Anthropic 的工具执行感和 Nature 的可信度组织画面。
2. 只保留一个可复述主张。原片最后收敛为“大模型负责规划和修正，数据与证据决定答案”。
3. 从真实运行产物取数，先核对输入表、统计值、图表和最终文件，再写分镜，禁止用占位数字冒充产品能力。
4. 用 HTML/Canvas 构造可控画面，Playwright 按时间渲染每一帧，FFmpeg 编码和混音；这样字幕、镜头、停留和状态出现时间都可复现。
5. 每个界面变化必须有因果：等待点击、按钮响应、结果生成、停留阅读、进入下一状态。点击前不得提前出现结果、计时或报告。
6. 镜头只服务于当前重点。需要强调按钮时只看按钮，需要强调数据时完整展示数据，移动后必须留出阅读时间，不能连续扫过页面。
7. 用关键帧而不是代码自证。逐次检查点击前后、图表边界、标题完整性、内容停留和结尾收束，最后检查时长、分辨率、音频响度和完整解码。

## 本项目的应用

本项目没有继续展示“总览、缩放、透镜、执行流程”四项功能，而是把主张收敛为：

> 让 Agent 的下一步，始终扣住根本目标。

20 秒只保留四个段落：

1. 提出长期对话后的根本问题：模型是否仍记得为什么做。
2. 用真实总览界面固定根本目标、当前进度和当前问题。
3. 用真实关系图说明缩小时先看方向，下一步始终有出处。
4. 用真实节点卡片演示 `NextIdea → Codex → CurrentResult`：写清下一步、交给 Agent、把结果回写到树，再回到核心主张。

渲染器是 `scripts/capture-readme-media.mjs`。它从本地任务图服务抓取真实界面元素，同时记录总览字段、主干节点、NextIdea、运行按钮和结果字段在截图中的归一化位置。左侧标签与右侧真实界面共用同一个连续动画状态和语义色，因此标签切换时，对应截图区域会同步提亮、描边和轻微聚焦。位置来自 DOM 而不是手写像素坐标，界面布局变化后重跑脚本即可重新取景。

脚本按固定时间轴逐帧生成 `1600x900`、`30fps`、20 秒的 MP4/WebM 和封面，不需要手工剪一遍旧录屏。焦点卡的内部取景会临时解除滚动容器裁剪，只影响截图素材，不修改产品界面。

## 验收清单

- 开场一句话能否独立解释产品价值。
- 每个场景是否只承担一个信息任务。
- 真实界面和文字是否完整、可读、没有重叠。
- 状态变化是否有原因，结果是否在动作之后出现。
- 左侧状态与右侧截图是否指向同一内容，语义色、提亮和路径是否同步。
- 切换中间帧的文字是否仍清晰，不能只检查每段稳定状态和封面。
- 每次移动或切换后是否留出阅读时间。
- 成片是否为 16:9，且视频、音频完整解码。
- 背景音乐是否可听但不压过文字和界面。
