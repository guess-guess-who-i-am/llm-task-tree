## task-tree.md · N3

### Problem

旧值：

多个 Agent 如何并发修改代码和运行服务，又不互相覆盖或污染共享状态？

→ 新值：

允许多个 Worker 同时修改代码与任务树，冲突由对话协商合并，结果自动应用并只展示进度。

### Approach

旧值：

写集/资源租约隔离运行，带来源 JSON 和 scope 隔离语义；共享目标和证据；接受/发布串行加锁、校验与回滚。

→ 新值：

完整上下文一次规划；就绪任务全部并发；写集仅作提示；独立工作树执行，真实冲突续接双方对话，完成自动应用。

### Metrics

旧值：

写集/资源零越界、无来源事实零误入；新会话恢复目标/焦点；并发接受仅一成功，发布失败不破坏旧版。

→ 新值：

同文件和任务树保留双方结果；超过四个任务并发；追加即时执行；无需审批、测试或审核阶段。

### CurrentResult

旧值：

→ 新值：

真实 Git 已验证同文件与任务树合并、即时追加和自动应用；七路并发与完整上下文测试通过。真实模型浏览器全链路和 Mac 安装仍在验证，尚未全部完成。

### RootCauseAnalysis

旧值：

污染来自两层：写集不隔离端口/数据库/发布锁；自由摘要无来源，会把临时指令升级为长期事实。

→ 新值：

写集重叠不必串行；复用同一对话才会冲突，新增任务需分叉历史。项目外直接修改不受 Git 合并保护。

### NextIdea

## subtrees/N3-subtree.md · N3

### Problem

旧值：

允许多个 Worker 同时修改代码与任务树，冲突由对话协商合并，结果自动应用并只展示进度。

### Approach

旧值：

- Supervisor 先生成任务 DAG、独占写集和资源租约；同一写集改为串行依赖。
  - Worker 使用 detached worktree 和独立端口、数据库、容器、缓存及浏览器目录。
  - 确定性队列串行集成；集成 Agent 只修复语义兼容并重跑双方验收。
  - 接受与 8898 发布分别加全局锁、基线校验、预检和失败回滚。

→ 新值：

- 完整上下文一次规划；就绪任务全部并发；写集仅作提示。
  - 独立工作树执行；真实冲突续接双方对话；完成自动应用。

### Output

旧值：

并发隔离设计与故障注入门禁；docs/subtree-parallel/concurrent-agent-isolation-design.zh.md。

→ 新值：

### Metrics

旧值：

写集和共享资源零越界；并发接受最多一个成功；发布失败不影响 8898 旧版本，成功可追溯到接受提交。

→ 新值：

同文件和任务树保留双方结果；超过四个任务并发；追加即时执行；无需审批、测试或审核阶段。

### RootCauseAnalysis

旧值：

工作树隔离只能处理文件系统，不能隔离端口、数据库、缓存和发布环境；现有写集检查也不能替代跨运行的接受与发布锁。

→ 新值：

写集重叠不必串行；复用同一对话才会冲突，新增任务需分叉历史。项目外直接修改不受 Git 合并保护。

### CaseStudy

旧值：

- case 1: 两任务改同一文件 → 规划期拒绝或串行，不把可预见冲突留给集成 Agent。
  - case 2: 两任务改不同文件但共用数据库 → Git 无冲突仍会互扰，必须分配资源命名空间。

→ 新值：

- 两任务改同一文件和任务树，通过双方对话合并后同时保留结果。
  - 同节点同写集追加任务，从历史对话分叉，原任务未结束也立即执行。
