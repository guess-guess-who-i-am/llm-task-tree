# DeepSeek 工具轮数与上下文交接

本轮保留 DeepSeek 执行后端，不切回 Codex。实现的是本项目的摘要交接，不是调用 Codex 原生压缩接口。官方压缩文档读取返回 HTTP 403，未以未经核实的兼容性假设接入网关。

## 工具执行什么时候结束

`startDeepSeekTurn` 不再设置 40 轮或其他工具调用数量上限。模型正常结束、用户停止、已有执行期限到点或真实错误仍会结束执行。默认总期限仍为十分钟；单请求的故障重试和 Hook 行为不变。

独立读取的二十路限制是同时执行宽度：超过二十个读取会分批全部处理，不是只执行二十次。写操作之间的顺序约束保留，避免重复写入。

## 长上下文怎么处理

1. 保留两份视图：磁盘和聊天界面的完整文字对话，以及本轮传给模型的工作上下文。整理上下文只改变后者，不删除聊天、不截断导出。
2. 复用已有 70% 软阈值；输入规模估算计入工具定义，给输出预留空间。默认按 64000 token 的保守工作窗口处理，这不是网关真实模型容量的声明。可在同一个全局根环境文件设置 `MODEL_AGENT_MAIN_CONTEXT_WINDOW` 为实际窗口，不需要逐项目配置。
3. 全局与本轮系统规则、当前用户请求、图片输入、最近消息和最新完整工具调用/返回组保留原样。早期对话、已经消费过的工具结果进入摘要；不把工具调用和返回值拆成孤立消息。
4. 摘要使用相同 DeepSeek 配置和已有请求重试。普通历史合并打包，超长单条内容分片处理，尾部也送入摘要；片段是传输边界，不是机械丢弃。摘要保留目标、更正、约束、决策、状态来源、失败、未决问题与下一步。最新原话和当前文件高于派生摘要。
5. 对话摘要与原文一起原子保存至全局会话文件。内容指纹匹配时，续聊或共享 Worker 重启直接复用；编辑旧消息使指纹变化，会重新生成。不长期保存原始工具调用、工具结果和推理；当前工具历史的摘要仅在本轮内使用。
6. 若网关明确拒绝上下文过长，则整理历史再请求，不重做已执行工具。摘要期间可停止；摘要失败不删除原文。若单条当前请求、规则、图片或最新工具组本身放不进窗口，会明确报错，不静默裁掉内容或伪报成功。

界面增加“正在整理长上下文，完成后继续执行”。函数级记录包含 `timing.compactions` 的前后估算量、分片数、耗时，以及 `timing.summaryRequests` 的请求和重试记录。估算不等于官方分词器结果。

## 验证与边界

- 原 40 轮行为先复现失败，再验证连续 55 轮工具完成及第 45 轮停止；没有写入重放。
- 长历史提前整理、运行中工具历史整理、摘要停止、网关容量拒绝恢复、最新请求与工具组保留、原文尾部覆盖、修改历史使摘要失效均有针对性测试。
- 本机 HTTP 模型替身 + 真实共享 Worker 完成 50 次工具调用、两阶段上下文整理和真实 Worker 重启；原始对话完整保留，重启续聊复用磁盘摘要，不再次生成。
- 摘要是有损语义归纳，不能保证所有旧细节都进入摘要。历史全文仍可回看；不能将流畅摘要当成新证据，也不承诺真实上游稳定或所有任务更快。本轮未用真实网关测摘要质量/耗时，测试只能证明编排、存储、恢复和停止行为。

测试入口：`server/deepseek-context.test.js`、`server/deepseek-run.test.js`、`server/deepseek-dialogue.test.js`、`server/shared-agent-worker.test.js`。原有停止、编辑重发、全文导出和节点对话回归也保留。
