# 让当前焦点及相关上下文主动出现在任务树屏幕上

## 结论

当前任务树不应默认要求用户浏览全树。更合适的主视图是**任务驱动的焦点子树**：系统自动把当前节点移入视口，以当前节点为中心，只显示解释“现在做到哪里、根本任务是否完成、卡在哪里”所必需的关系；被隐藏的分支用可点击摘要提示，完整树按需进入。

这不是简单地放大 Current 节点。经典方法共同指向三个原则：

1. **局部细节与少量远程地标同时可见**，而不是所有节点同时可见（Furnas）。
2. **先从已知焦点生成有界上下文，再沿用户选择方向扩展**，而不是先画全图（van Ham & Perer）。
3. **焦点切换时保留祖先路径、相对位置和动画连续性**，避免用户重新寻找位置（SpaceTree）。

## 对当前任务树的具体推导

### 1. 默认主视图应显示什么

主视图应由系统主动生成，而不是让用户寻找节点。最低必要集合为：

- **ROOT 的根本任务与达成状态**：作为远程地标，不显示完整 ROOT 卡片。
- **当前阶段目标**：只保留能解释 Current 为什么存在的阶段问题或目标。
- **Current 节点**：完整显示“解决什么问题、采用什么思路、结果如何、剩余缺口”。
- **阻塞节点或阻塞关系**：仅当证据表明它直接阻止 Current 或阶段目标时显示。
- **Next 节点/下一未解决动作**：若与 Current 相同则不重复成两张卡。
- **连接上述节点所需的最短祖先/依赖路径**：中间节点可压成标题或路径段。

默认不应显示 Current 的全部兄弟、已完成历史分支、仅因拓扑相邻但与当前问题无关的节点。它们属于“可发现上下文”，不属于“默认上下文”。

### 2. 树如何主动提醒用户

系统每次打开、Current/Next 改变、出现 blocker 或树被写入后，应自动执行：

1. 将 Current 居中并恢复到可读尺度；
2. 计算上述必需集合；
3. 在屏幕边缘显示少量隐藏方向提示，例如“上游目标”“阻塞来源”“下一分支”；
4. 用户点击提示时，只扩展该方向的下一批高相关节点；
5. 焦点切换用稳定、分步动画，并保持祖先路径和节点相对方位。

这正对应“search/show context/expand on demand”：多数时候系统已有 Current，无需用户再次搜索；只有当用户查找其他问题时才使用搜索建立新焦点。

### 3. 如何控制信息量

不建议先规定任意固定节点数。论文支持的是**适配视口的有界集合**，不是普适数字阈值。可采用以下优先顺序填充屏幕：

1. 强制保留：ROOT 状态、阶段目标、Current、直接 blocker、Next；
2. 保证连通：连接这些锚点的路径；
3. 剩余空间：按任务 DOI 加入节点，兴趣来源包括用户搜索、明确阻塞、未完成状态、近期修改及结构距离；
4. 空间不足：先将路径中间节点降为标题，再隐藏低 DOI 分支；绝不把正文缩到不可读；
5. 隐藏内容：用带语义的摘要入口表示，而非仅靠数量或抽象三角形。

### 4. 不能由这些论文直接推出的部分

- 论文不能替本项目定义“根本任务是否完成”或“真正 blocker”；这些必须来自任务树语义和证据，而非仅靠图距离。
- DOI 权重与显示预算需要用本项目真实任务验证，不能照搬论文示例或自行设定固定阈值。
- 焦点视图不能取代完整树。完整树仍用于结构编辑、跨分支比较和审计，但应成为按需模式。
- 自动跳转若发生得过频会破坏空间记忆；应由语义事件触发，而不是每次小字段更新都重排。

## 建议的产品形态

保留任务树作为数据结构和关系载体，但把默认入口改为**自动聚焦的任务树切片**：

> 根本任务状态 → 当前阶段 → Current（问题 / 思路 / 结果 / 缺口）→ blocker 或 Next

其他分支不消失，而是以“关系方向”主动提醒。用户需要全貌时再进入完整树；需要其他节点时搜索并建立临时第二焦点。这样利用了树对联系的表达能力，同时避免把“全貌”强加给日常推进。
