## N6 - 节点内多模型协作
- Position: 1350,950
- Size: 520,720
- Completion: 已完成
- Problem: 用户希望在每个任务图节点内配置多个不同模型，并让它们基于整棵 task-tree.md 和各自历史/agent.md 独立思考当前节点问题。
- Approach:
  - 在节点标题下方增加同宽“模型协作”栏，打开右侧同高面板。
  - 本地保存多个模型配置：base_url、api_key、model、wireApi、启用状态；API key 不写入 task-tree.md。
  - 每个模型有独立 `model-agents/<id>.md` 作为 agent prompt，并在 `model-agent-history.json` 中保存该模型自己的节点历史。
  - 运行时把整棵 task-tree.md、当前节点 Markdown、用户问题、该模型历史和 agent prompt 一起发送给模型；多个模型并发独立回答。
  - 当前改为每个模型独立拥有临时会话上下文；用户可以只勾选一个模型进行多轮对话，也可以勾选多个模型并行对话。
  - 每个模型不再被动接收同一批统一检索结果，而是在服务端工具循环中自行决定是否请求检索；服务端按它给出的 search JSON 调用本地知识库和联网搜索，再把结果回填给该模型。
  - 每个模型运行时会收到页面内其它模型围绕同一节点的临时共享上下文，但这些内容不落盘、不写入 task-tree.md，刷新页面后消失。
- Input: task-tree.md、当前节点、用户填写的问题、model-agents.json、model-agent-history.json、model-agents/<id>.md、OpenAI-compatible base_url/api_key/model。
- Output: 节点内多模型协作栏、模型配置面板、并发运行接口、模型独立回答和本地历史记录。
- Metrics:
  - 可以在网页中新增/保存多个模型配置，不暴露 api_key 到 task-tree.md。
  - 每个节点能打开同宽模型协作栏并勾选多个模型运行。
  - 每个模型看到整棵树、当前节点、自己的 agent.md、自己的临时会话历史，以及其它模型在当前页面内的临时共享上下文。
  - 每个模型能自己决定要检索什么关键词，而不是只能看同一批预检索上下文。
  - 运行结果按模型分开展示，失败模型显示明确错误。
- Notes: 当前实现先做独立并排回答，不做 judge 融合；融合/裁判可以作为下一步扩展。
- CurrentResult: v2 Worker N6 完成 API 路由审计：grep+局部读 server.js 确认 `/api/model-agents` 仅 3 条路由（GET 列表+agentPrompt、PUT 保存配置、POST run 并发+工具检索+树快照 hash）。详文见 docs/subtree-parallel/v2-N6-findings.md。实现与子树 Metrics 对齐：key 不进 task-tree、临时 history/shared 不落盘、分模型 ok/error 响应。
- RootCauseAnalysis: 多模型协作的核心隐患是隐藏记忆边界：持久历史会让用户不知道后续模型看过什么，运行中重读 task-tree.md 又会受用户正在编辑的内容干扰。因此当前采用页面内临时记忆 + 运行开始时树快照，刷新即清空，运行中不再读磁盘树。
- CaseStudy:
  - case 1: 如果把 api_key 写进 task-tree.md，模型和前端都能看到密钥，违背任务图作为共享上下文的边界；因此密钥只进 gitignored 的 model-agents.json。
  - case 2: 如果多个模型共享同一段历史，会破坏“独立专家”效果；因此历史按 modelId 分开保存，并只在对应模型 prompt 中注入。
  - case 3: 如果只给当前节点，不给整棵树，模型会失去任务全局背景；因此运行接口直接读取最新 task-tree.md 作为权威上下文。
  - case 4: 如果模型回答写入历史文件，用户会误以为“只看本次”的协作结果会长期影响后续模型判断；因此本轮改为不保存历史、不写任务树，只在当前 UI 中展示。
  - case 5: 统一按用户问题预检索再广播给所有模型，会让模型失去“自己判断该查什么”的能力；因此改成由模型请求 search，服务端执行检索并回填结果。
  - case 6: 如果关闭/重新打开面板就丢失对话，无法和单个模型多轮澄清；如果写入磁盘又会形成长期隐性记忆。当前折中是页面内临时会话，刷新页面后消失。
  - case 7: 如果不同模型完全看不到彼此临时对话，用户会在“多模型一起想”后仍要手工转述上下文；如果写入磁盘，又会形成用户不想要的长期隐性记忆。当前折中是页面内 sharedHistories。
- NextIdea: 下一步可以增加一个“融合裁判模型”，把多个模型回答归纳成共识、分歧、盲点和推荐写回节点 CurrentResult/NextIdea。
